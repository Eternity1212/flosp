> **这个解离在机制上是可预期的，但在本数据上它背后只有约 7 例净翻转，

三个数字（均为点估计）：

| 端点 | FedAvg | FedOSP-R | 变化 | 方向 |
|---|---:|---:|---:|---|
| 等级 MAE | 0.4928 | 0.4623 | **−0.0305** | 有利 |
| ≥2 级误判率（T7 主指标） | 0.1393 | 0.1271 | **−0.0122** | 有利 |
| **referable 敏感性** | **0.7109** | **0.6947** | **−0.0162** | **不利** |

⚠️ 另有一处与机制方向相反的发现：§3 的内部一致性核对表明，

即这份 QWK/MAE 收益**不是**（至少不只是）向刻度中心收缩买来的。
这进一步削弱"解离已经发生"的读法。

## 2. 机制：距离加权端点与阈值端点在阈值附近被反向优化

### 2.1 QWK 的确切代数，以及换算率的正确值

QWK 的权重是 $w_{ij}=(i-j)^2/16$。把观测与期望都展开，$1/16$ 约掉，得到一个
对本节全部论证足够的精确形式：

$$\mathrm{QWK} = 1 - \frac{\sum_i(\hat y_i-y_i)^2}{S_2+T_2-2S_1T_1/N}$$

其中 $S_1,S_2$ 是真实标签的一、二阶矩和，$T_1,T_2$ 是预测标签的一、二阶矩和。
**分子就是平方误差和（SSE），一次距离为 $d$ 的误判恰好贡献 $d^2$。**

于是"修掉一次远端误判，可以换多少次邻级误判而 QWK 不变"有确切答案：

| 远端误判 | 分子代价 | **换算率（可换的邻级误判数）** | 台账 §6.3 写的 |
|---:|---:|---:|---:|
| $d=2$ | 4 | **4** | ~3 |
| $d=3$ | 9 | **9** | ~3 |
| $d=4$ | 16 | **16** | ~3 |

分母 $T_2,T_1$ 也会随预测分布变化，所以换算率不是严格的 $d^2$。
实测这项反馈很小：把 2% / 5% / 10% 的极端**预测**各向内收一步，
分母只移动 **−0.4% / −1.0% / −1.7%**；在 Messidor-2 的边际上做 200 次
随机置换的数值核对给出的实际盈亏平衡点是 **d=2 → 5.6 次、d=3 → 10.5 次**
（略高于 $d^2$，因为修掉远端误判本身也会轻微抬高分母）。

> 📌 **与台账 §6.3 的差异，须由台账 owner 决定怎么处理。**
> §6.3 写的是"远端误判（$d\ge3$）折算成邻级误判约为 **3:1**"，
> 而 QWK 的代数给出 **9:1**（$d=3$）与 **4:1**（$d=2$）。
> **差异的方向对本文有利但对 §6.3 的原用途不利**：
> 换算率越大，QWK 对"远端换邻级"越宽容，所以
> ① §2.3 的机制假设比 3:1 下更可信（向中心收缩更划算）；
> ② 但 §6.3 用这个常数解释的是"C1 降低了远端误判、QWK 却不动"——
> 在 9:1 下这需要邻级误判增加得**比原文说的多 3 倍**才能抵消，
> 该段的定量结论因此需要重算。本文不修改台账，仅登记（见 §8）。
> 本文自身的全部论证都用代数值 4:1 / 9:1，不依赖 3:1。

### 2.2 referable 阈值的结构：阳性类的 76% 离阈值只有一步

referable 的定义是 grade ≥ 2（`fedosp/metrics.py::REFERABLE_THRESHOLD = 2`），
所以阈值落在 **grade 1 与 grade 2 之间**。按仓库登记的 Messidor-2 等级分布
（`EXPECTED_GRADE_DIST["messidor2"] = [1017, 270, 347, 75, 35]`），阳性类的构成是：

| 真实等级 | 例数 | 占阳性类 | 跨过 1\|2 阈值需要几步 |
|---:|---:|---:|---:|
| 2 | **347** | **75.9%** | **1** |
| 3 | 75 | 16.4% | 2 |
| 4 | 35 | 7.7% | 3 |
| 合计 | **457** | 100% | — |

**阳性类的 75.9% 是 grade 2，而 grade 2 距离阈值只有一步。**
这是本节的核心结构事实：referable 敏感性几乎完全由 grade 2 的判读决定。

### 2.3 两个端点在同一个动作上符号相反

把上面两件事放在一起，机制就是一句话：

> **把 grade 2 的预测向 grade 1 挪一步，对 QWK 只花 1 个 SSE 单位
> （可由任意一次 $d\ge2$ 的修复以 4:1 或 9:1 的比价买回），
> 但它直接把一个真阳性变成假阴性。**

两个端点对同一动作的读数：

| 动作 | SSE | MAE | ≥2 级误判率 | referable 敏感性 |
|---|---:|---:|---:|---:|
| 真 2 预测 2 → 预测 1 | +1 | +1 例 | 不变 | **−1 例** |
| 真 2 预测 0 → 预测 1 | −3 | −1 例 | **−1 例** | **不变**（仍是假阴性） |
| 真 4 预测 1 → 预测 2 | −5 | −1 例 | 不变 | **+1 例** |

第二行尤其要注意：**把一个 $d=2$ 的假阴性改成 $d=1$ 的假阴性，
QWK、MAE、≥2 级误判率三个指标全部改善，referable 敏感性一动不动。**
也就是说 T7 与 referable 敏感性并不是同一件事的两种说法，
它们在 grade 2 的非转诊侧完全脱钩。

**所以"QWK/MAE 改善、referable 敏感性下降"在机制上不是异常，而是可预期的。**
距离加权端点奖励"错得近"，阈值端点只问"在阈值的哪一边"；
而阳性类的 76% 恰好贴着阈值，是最便宜的让步对象。

## 3. 内部一致性核对：1.22 pp 与 0.0305 对得上吗

### 3.1 下界：≥2 级误判下降能供给多少 MAE 改善

用尾和恒等式（对任何序数预测都精确成立）：

$$\mathrm{MAE} = \sum_{d\ge1} P(|\hat y-y|\ge d) = P_1+P_2+P_3+P_4$$

如果 1.22 pp 的 ≥2 级误判**全部**恰好从 $d=2$ 落到 $d=1$，其它一律不变，那么

$$\Delta\mathrm{MAE} = -0.0122\times 1 = -0.0122$$

这是"远端换邻级"这条通道能提供的 MAE 改善的**下界**（若有 $d\ge3$ 的更深压缩则更多）。

### 3.2 对照观测值

| 项 | 值 |
|---|---:|
| 由 ≥2 级误判下降供给的 MAE 改善（下界） | **0.0122** |
| **实测 MAE 改善** | **0.0305** |
| 倍数 | **2.50×** |
| **残差（无法由这条通道解释）** | **0.0183**，占实测改善的 **60.0%** |

残差折算成例数：$0.0183\times1744 = $ **31.9 张**（而 ≥2 级误判下降对应 21.3 张）。

### 3.3 残差说明什么——而它说的事与"向中心收缩"相反

由尾和恒等式，残差必须由另外三项承担：

$$\Delta P_1+\Delta P_3+\Delta P_4 = -0.0183$$

**"向中心收缩"这个机制预测 $\Delta P_1 > 0$**（邻级误判增加，因为原本判对的
grade 2 被拉到 grade 1）。若要同时满足恒等式，就必须

$$\Delta P_3+\Delta P_4 < -0.0183$$

再用 $P(\!=\!2)=P_2-P_3$ 得到一个可直接核验的推论：

$$\Delta P(\!=\!2)\;=\;\Delta P_2-\Delta P_3\;\ge\;-0.0122+0.0183\;=\;\boxed{+0.0061}$$

即**恰好差 2 级的误判必须增加至少 0.61 pp，同时 ≥3 级误判必须下降至少 1.83 pp**。
这是"向中心收缩发生在尾部深处（3→2、4→2）"，**而 3→2 和 4→2 都不跨过 1\|2 阈值**，
因此这一支并不产生 referable 敏感性损失。

另一支更简单：Messidor-2 只有 **6.3%**（110/1744）的样本是 grade 3 或 4，
所以 $P_3,P_4$ 本身很小，近似不变是合理的默认假设。若 $\Delta P_3=\Delta P_4=0$，则

$$\Delta P_1 = -0.0183 \quad\Longrightarrow\quad \text{总误判率下降 } 1.83\ \text{pp}$$

也就是 FedOSP-R 只是**更准**了，邻级误判在减少而不是增加，
这份 QWK/MAE 收益根本不是在阈值上买来的。

### 3.4 这一节的结论

**三个数字内部自洽，但它们不支持"QWK 收益由向中心收缩购得"这个读法。**
要让"向中心收缩"成立，必须同时出现 $\Delta P(\!=\!2)\ge+0.61$ pp 与
$\Delta P_3\le-1.83$ pp；而这两件事都发生在远离 referable 阈值的地方。
两支都指向同一个结论：**referable 敏感性的下降在当前算术下缺少机制支撑**，
更像是噪声，而这正是 §4 要定量确认的。

> 这一节只需要双方已有的混淆矩阵就能判定走哪一支：
> 逐 seed 报出 $P(\!=\!1)$ / $P(\!=\!2)$ / $P(\!=\!3)$ / $P(\!=\!4)$ 四格即可，零 GPU 成本。
> 已列入交接件（`交接_P0证据链后续_2026-10-02.md` 第 2 项）。

## 4. ★ 量级核验：这件事背后有多少例

**这一节决定结论的档位，所以放在机制之后、检验之前。**

### 4.1 referable 子集规模与它依赖的假设

**明确声明的假设**，三条，缺一条下面的例数都不成立：

1. **等级分布取仓库登记值** `EXPECTED_GRADE_DIST["messidor2"] = [1017, 270, 347, 75, 35]`
   （`fedosp/data/build_manifest.py:66`，总和 1744）。
   旁证：由它算出的 referable 占比 **26.204%** 与台账 §6 实测的 **26.20%** 吻合，
   与 §12.3 Brier 口径核定用的同一把参照尺一致，所以这个边际是可靠的。
2. **referable = grade ≥ 2**（`fedosp/metrics.py:23`），阈值在 grade 1 与 2 之间。
3. **敏感性的分母是真阳性数，不是全体**。即 $n_{\text{pos}} = 347+75+35$。

$$n_{\text{pos}} = \mathbf{457}\quad(26.20\%\ \text{of}\ 1744)$$

⚠️ 若协作方实际用的分母不是 457（例如在全体 1744 上算、或 referable 取 ≥1、
或先做了阈值标定），本节全部例数失效，**必须先核对再引用**。
这是引用这三个数之前的第一道必做核对。

### 4.2 净翻转例数

| 量 | 值 |
|---|---:|
| 1 例在敏感性上的刻度 | $1/457 = $ **0.219 pp** |
| FedAvg 敏感性 0.7109 | ≈ 324.9 例命中 |
| FedOSP-R 敏感性 0.6947 | ≈ 317.5 例命中 |
| 下降 1.62 pp | **净翻转 7.40 例** |

**7.4 例。** 作为对照：

| 对照量 | 值 | 折算成例数 |
|---|---:|---:|
| 单臂二项抽样 SE（$p{=}0.71$, $n{=}457$） | **2.12 pp** | **9.7 例** |
| 朴素非配对差值 SE | 3.02 pp | 13.8 例 |
| 观测下降 | 1.62 pp | **7.4 例** |

**观测到的下降小于单臂自身的抽样 SE。** 这一句基本就把"发现"这个档位排除了。

### 4.3 McNemar 的硬约束：要显著，两臂必须在 96.9% 的阳性例上完全一致

阈值指标的配对检验是 McNemar。记两臂不一致的例数为 $b+c$、净差为 $b-c=7.4$，
则 $z=(b-c)/\sqrt{b+c}$：

| 不一致例数 $b+c$ | 占 457 | $z$ | $p$ |
|---:|---:|---:|---:|
| 14 | 3.1% | 1.98 | **0.048** |
| 20 | 4.4% | 1.66 | 0.098 |
| 30 | 6.6% | 1.35 | 0.176 |
| 46 | 10.1% | 1.09 | 0.275 |
| 96 | 21.0% | 0.76 | 0.450 |
| 192 | 42.0% | 0.53 | 0.593 |

**要 $p<0.05$，需要 $b+c\le 14.3$ 例，即两臂必须在 457 个阳性例中的 96.9% 上
给出完全相同的转诊判断。** 在一个 seed 间 QWK SD 已经是 **0.033**、
配对差 SD 对 FedAvg 是 **0.0272** 的设置里，这个一致度不可能成立。

**因此：即使拿到配对数据，这个下降极可能判不动。** 这不是悲观，这是事先算出来的
分辨力——和骨架 §4.2 对 QWK 做的事完全一样，只是换了个端点。

### 4.4 这个下降在主端点上的足迹：0.0020 QWK

最后一个核验，它解释了为什么两个端点在当前量级上**并不冲突**。
用 §2.1 的精确形式，取预测边际 ≈ 真实边际（台账 §6 实测 FedAvg 的 referable
软预测占比 26.46% vs 真实 26.20%，差 0.26 pp，足够近），分母

$$D = S_2+T_2-2S_1T_1/N \approx 2\!\left(S_2-S_1^2/N\right) = 3760.5$$

于是**一次额外的邻级误判只值 $1/3760.5 = 2.66\times10^{-4}$ QWK**。那么：

| 量 | 值 |
|---|---:|
| 7.40 例翻转的 QWK 代价 | **0.0020** |
| 占实测 QWK 增益 +0.0290 | **6.8%** |
| 占本比较自身的 $\sigma_d$ = 0.0272 | **7.2%** |
| 占 n=10 的 CI 半宽 ±0.0195 | **10.1%** |

**整个 referable 敏感性下降在主端点上只值 0.0020 QWK，是本比较噪声的 7%。**
所以"QWK 改善而敏感性下降"在这个量级上**不是一对矛盾的读数**：
QWK 根本看不见 7 例。两个端点真正开始互相为难，需要翻转量级大一个数量级。

### 4.5 一条已有的同向线索，以及它如何化解 AUROC 与敏感性的表面冲突

台账 §6 的机制诊断里有一条早就记下的量，方向与本节一致：

| 量 | FedAvg | FedOSP | 真实 |
|---|---:|---:|---:|
| 平均**软预测** referable 占比 | 26.46% | **23.76%** | 26.20% |

两臂相差 **−2.70 pp**，折算到 1744 张是**少判约 47 张**为 referable。
这正是"工作点向少转诊一侧移动"的直接证据，而且它是**独立于本次 per-class 审计**
就已经在仓库里的。

⚠️ **但不能直接拿来当本节的证据，两处口径不同**：
① §6 测的是 **FedOSP**（FSR 开启 + sqrt 聚合），**不是 FedOSP-R**（`--no-fsr --param-weight sample`）
——而 sqrt 聚合已被判**有害**（台账 §9 C4），两者的边际行为不可互换；
② §6 是**软预测的概率质量**，本节是 **argmax 后的硬判读**。
所以它只能作为**方向一致的线索**，请在交接件第 2 项里让协作方
**对 FedOSP-R 直接报出 argmax 后的 predicted-positive 计数**。

**不过这条线索顺手化解了台账 §13.9 第 3 条登记的那处冲突**：
referable AUROC **+0.0090，10/10 seed 同向**（改善），而敏感性**下降**。
两者可以同时为真，而且现在能说清是怎么同时为真的：

| 量 | 读数 | 它量的是 |
|---|---|---|
| referable AUROC | **+0.0090，10/10 同向** | **区分度**（无阈值，与工作点无关） |
| referable 敏感性 | **−0.0162（约 7.4 例）** | **某一个工作点**上的召回 |
| 预测 referable 占比 | **−2.70 pp（FedOSP，仅线索）** | **工作点本身移动了多少** |

**合起来是一句话：区分度在改善，而 argmax 隐含的工作点向"少转诊"一侧移动了。**
若预测阳性总数的降幅（约 47 张）确实大于真阳性的降幅（约 7.4 例），
那么**特异度是在上升的**——这是一次工作点平移，不是区分度损失。

**后果（两条，都是纪律）**：

- ✅ 这意味着"QWK/MAE 改善而敏感性下降"**不构成矛盾**，也不需要诉诸 QWK 的
  权重结构来解释。**用更少的假设就能说明同一组数字，所以 §2 的机制假设并非必需。**
  这是本文把它定为"未证实"的第三个独立理由（前两个是 §3 的算术与 §4.2 的例数）。
- ❌ **不得把 AUROC 的改善概括成"重症检出改善"**（台账 §13.9 第 3 条已立此禁令）。
  AUROC 改善 + 敏感性下降 + 工作点左移，正确的写法是
  "区分度改善，而 argmax 工作点更保守"，三件事分开写。
- 📌 **如果要报告工作点，就必须同时报特异度 / 预测阳性数。**
  只报敏感性下降而不报特异度，与 §5.3 禁止的那种不对称是同一个错误。

| 成立 | ❌ 没有配对 CI；且 §4.3 表明即使有也极可能跨零 |
| 不成立（精确零） | ❌ 同样需要配对 CI 才能给上界 |
| **未证实** | ✅ **就是这一档** |

> **本文的正式判定：指标解离在本数据上是"未证实"。
> 它是一个有机制支撑、有明确检验、零 GPU 成本可判的假设，不是一个发现。**

## 5. 指定的检验（写在看到任何配对数字之前）

### 5.1 设计：和 QWK 比较用同一套机器，零 GPU 成本

| 项 | 规定 |
|---|---|
| 数据 | 已有的 50 个 run（5 方法 × seed 3–12）的 `predictions.npz`，**不跑任何新实验** |
| 单位 | 逐 seed 算 referable 敏感性，按 seed 配对取差 |
| 统计 | 配对 t，95% CI，同时报 $\bar d$ / $\sigma_d$ / 同向 seed 数 / $d_z$ |
| 样本量 | n = 10（与主端点同一批 seed，严格配对） |
| 口径 | 与 QWK 逐字相同：`fedosp.stats` 现成实现；CI 半宽 $=0.71536\,\sigma_d$ |

**为什么这是正确的单位。** 骨架全文的 CI 都是 seed 层配对 t，量的是训练随机性；
把 referable 敏感性放进同一个框架，这个端点才能和主端点并排读。
用样本层 bootstrap 会换掉随机性来源，两个端点的 CI 就不再可比。

### 5.2 事先写下它需要多紧才判得动（以及预期判不动）

$t_{0.975,9}=2.2622$，半宽 $=0.71536\,\sigma_d$。要让 95% CI 不跨零：

$$\sigma_d(\text{sens}) < \frac{0.0162}{0.71536} = \mathbf{2.26\ pp}$$

要有 80% 功效（MDE ≈ 0.996 $\sigma_d$）：$\sigma_d \le \mathbf{1.63\ pp}$。

**对照：单臂二项抽样 SE 本身就是 2.12–2.15 pp（§4.2）。**
也就是说，所需精度低于单臂抽样噪声独自提供的量级。

| $\sigma_d$(sens) 假设值 | CI 半宽 | MDE（裸） | MDE（Holm 族=3） | 能否检出 −0.0162 |
|---:|---:|---:|---:|:---:|
| 1.00 pp | ±0.72 pp | 1.00 pp | 1.22 pp | ✅ |
| 1.47 pp | ±1.05 pp | 1.46 pp | 1.80 pp | ✅ 裸 / ❌ Holm |
| 2.14 pp | ±1.53 pp | 2.13 pp | 2.62 pp | ❌ |
| 2.72 pp | ±1.95 pp | 2.71 pp | 3.33 pp | ❌ |

> **事先声明的预期：这个检验很可能给出跨零的 CI。**
> 把预期写在这里，是为了让它成为一次**预先指定的检验**而不是一次事后捞取。
> 两种结果都可写：CI 跨零 → 解离在本设置下未证实（且 §4.4 说明它在主端点上
> 只值 0.0020 QWK，不构成冲突）；CI 不跨零 → 一个带区间的次要端点发现，
> 此时才可以、也必须按 §5.3 的对称要求报告。

### 5.3 ★ 对称性要求：有利与不利的次要端点必须同一把尺子

**这是本文最硬的一条纪律，优先于任何机制叙事。**

现有次要端点的处理已经不对称：MAE 与 ≥2 级误判率（**方向有利**）和
referable 敏感性（**方向不利**）目前都只有点估计，但在叙述里前两个被当成"改善了"，
第三个被当成"需要解释的异常"。两者的证据强度完全相同：都是**无区间的点估计**。

规定（任选其一，但必须对三个端点同时适用）：

| 方案 | 做法 |
|---|---|
| **A（推荐）** | 声明一个次要端点族 {MAE, ≥2 级误判率, referable 敏感性}，族内 Holm 校正，三个端点一起报 Δ / CI / $\sigma_d$ / 同向数 |
| B | 三个全部标注为 **exploratory**，一律不做显著性声称，只报点估计与"无区间"的限定词 |

**禁止**：对有利的端点报"改善"而对不利的端点报"落在噪声内"。
反之亦然——不得只把不利端点写成发现而把有利端点一笔带过。
（这条纪律与台账 §4.2"阳性与零不得并列陈述为承担同等选择风险"同源：
那一条管的是选择偏差的方向，这一条管的是证据标准的对称。）

### 5.4 阈值指标的统计口径：不要用非配对区间

三条，按重要性：

1. **用 McNemar 或配对比例区间，不要用非配对区间。**
   两臂评的是同一批 457 个阳性例，非配对 SE（§4.2 的 3.02 pp）把两臂共同的
   "样本难易度"方差算进了误差，白白损失功效——和 `benchmark_table.py` 坚持
   按 seed 配对的理由一字不差。**样本层请报 McNemar 的 $b$、$c$ 两个计数**，
   它们本身就是可审计的量（而且 §4.3 的表格可以直接套用）。
2. **两个层次要分开报，不要混成一个数。** seed 层配对 t 量训练随机性（§5.1），
   样本层 McNemar 量病人抽样。两者回答不同问题，骨架 §4.6 的方差分解已经
   区分过这两项；这个端点也要照办。
3. **几百例上的比例，必须报例数而不只报百分比。** 本文 §4.2 就是这条的演示：
   1.62 pp 看起来像个效应，7.4 例看起来像噪声，**而它们是同一个数**。
   建议论文里凡出现 referable 敏感性，一律并排写 `0.6947（317.5/457）`。

### 5.5 病人级聚类：Messidor-2 约两张图一人

Messidor-2 是 1748 张 / 约 874 次检查，**约 2 张图对应 1 个病人（双眼）**。
DR 是双侧疾病，同一病人两眼的等级高度相关，所以 457 个阳性"例"不是 457 个独立单位。

| 眼间 ICC | 设计效应 $1+(m-1)\rho$ | 有效 n | CI 变宽 |
|---:|---:|---:|---:|
| 0.3 | 1.30 | 352 | ×1.14 |
| 0.5 | 1.50 | 305 | ×1.22 |
| 0.7 | 1.70 | 269 | ×1.30 |

**后果**：样本层区间还要再宽 14%–30%，§4.3 已经很严的约束只会更严。
实现这件事需要 ADCIS 的官方配对表（台账 §12.2 已登记为待办），
而病人级 bootstrap 还额外需要 NPZ 的顺序可恢复性——见交接件第 3 项。

## 6. 从兄弟项目 `recheck_metric_dissociation.py` 复用了什么

读的是 `fl-agent_experiment_package_20260819/4_manuscripts/recheck_metric_dissociation.py`
（同一用户的另一个项目，处理的正是 AUROC–F1 的"指标解离"主张）。

### 6.1 直接复用的（已落进本文）

| 可复用项 | 原文怎么做 | 本文怎么用 |
|---|---|---|
| **把解离主张逼成一个带统计量的命题** | "The dissociation claim is fundamentally about method ORDER … so the test is a Spearman rank correlation" | §5.1：把"解离"逼成"逐 seed 配对的敏感性差 + CI"，而不是一段叙述 |
| **判据写在看到数字之前** | 脚本末尾的 `VERDICT` 段把阈值（`ap_mean > 0.7`、`f1_mean < ap_mean − 0.2`）与对应结论文字写死在代码里 | §5.2：事先写下"需要 $\sigma_d<2.26$ pp 才判得动"**和**"预期判不动"，两种结果的写法都先定好 |
| **先问第二个指标是不是 oracle 量** | 发现 `best_micro_f1` 的阈值是在测试集上搜 macro-F1 最大化得来的，因此是 test-peeking | §4.1 假设 2/3：先核对 referable 的阈值是不是固定的。**本项目这里是干净的**——阈值是 `REFERABLE_THRESHOLD = 2` 常量 + argmax，没有任何标定，所以本文不存在那个混杂。这一点值得在论文里明写（它是与兄弟项目的实质差别） |
| **"阈值指标 vs 免阈值指标"这组术语与切分** | AUROC/AP（免阈值）对 best-F1（阈值） | §2.3：距离加权端点（QWK/MAE）对阈值端点（referable 敏感性）。同一条骨架，换了指标族 |
| **先做退化/刻度自检再解释** | `endpoint_hits`：统计有多少 run 的 oracle 阈值贴在搜索网格边界上，贴边就说明搜索退化而非找到内部最优 | §4.2：先算"1 例 = 0.219 pp"这个刻度，再解释 1.62 pp。**这一条是本文结论的来源** |
| **同一格重复产物的去重纪律** | `DIR_PRIORITY` + 冲突清单：同名 run 出现在多个目录且值不同时，必须挑一个规范副本，否则"会静默改变 seed 数和均值" | 交接件第 4 项：协作方 50 run 未入 git 且 run 内不嵌 git hash，正是这个失效模式的温床 |
| **声明 SD 口径** | `Std uses ddof=0 to match the manuscript's reported spreads` | §5.1：明写配对 t（ddof=1），避免与兄弟项目的 ddof=0 混读 |

### 6.2 刻意不复用的

- `ARCHIVE` 路径、`parse_name` / `TWO_TOKEN_METHODS` 的 run 名解析、
  `ODIR_DIRS` 的数据集切分：全部绑定那个项目的目录布局。
- macro-AP / 多标签指标与 RFMiD/ODIR 的标签语义：本项目是 5 类序数单标签。
- 那边的具体阈值（0.7 / 0.2）与 Spearman 统计量：
  本项目的"解离"不是**方法排序**问题（只有两个臂），而是**同一对臂上两个端点
  符号相反**的问题，所以排序相关性在这里没有定义。换成配对差 + CI 是正确的类比。
- 任何数字。两个项目的数据集、指标、样本量都不同。

### 6.3 一句话总结

> 兄弟项目那份脚本给的不是代码，是**流程**：
> 先问第二个指标干不干净 → 再把主张逼成一个统计量 → 判据事先写死 → 最后才解释。
> 本文按这个顺序走，结果在第一步半（刻度自检）就定了档位。
