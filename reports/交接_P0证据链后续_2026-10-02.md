## 1. ★ 机制阶梯三格的配对 CI：零成本、最大升级

**做什么。** 用已有的 50 个 run，在 seed 3–12 上**按 seed 配对**直接计算：

| 推得比较 | 现有（点估计，无区间） | 需要的 |
|---|---:|---|
| **FedProto − FedAvg** | ≈ +0.0286（占 98.4%） | $\bar d$ / $\sigma_d$ / 95% 配对 t CI / 同向 seed 数 / $d_z$ |
| **FedProx − FedAvg** | ≈ +0.0003（占 1.0%） | 同上 |
| **MOON − FedAvg** | ≈ +0.0027（占 9.3%） | 同上 |

不需要任何新实验，也不需要改任何面板：这三格就是**换一次配对方式**
（`scripts/benchmark_table.py --ref bench_fedavg`，或在你们的统一审计
`audits/final/paired_core_methods_seed3_12.json` 上重算）。

**为什么它承重。**

论文骨架 §5.1 把机制阶梯定为**解释层的骨架**——"这份 +0.029 的增益落在哪一层机制上"
是全文唯一的正向叙事。**而它现在是全文支撑最弱的一个对象**：三个份额都是
两个点估计相减，**各自没有任何区间**，按骨架 §0.1 的三档判定只能记"未证实"。

最能说明问题的是 FedProx 那一格。台账 §4.1 / §5 已经记下它的代数边界：

$$0.0070 \;\le\; \sigma(\text{FedProx}-\text{FedAvg}) \;\le\; 0.0474$$

对应 n=10 的 CI 半宽 **±0.005 到 ±0.034**，**相差近 7 倍**。后果很具体：

| 若真实 $\sigma_d$ 落在 | CI 半宽 | 那句话变成 |
|---|---:|---|
| 0.0070（下端） | ±0.005 | **一个很强的精确零**：已排除 +0.005 以上的增益，可以进骨架表 2 |
| 0.0474（上端） | ±0.034 | **什么都说明不了**：连 +0.03 都排除不掉 |

也就是说，**"一个专门为异质性设计的方法在这个设置下没有增益"这句话，
目前完全没有误差棒**，而它恰好是论文用来回答"FedAvg 是不是稻草人"这条审稿意见的
核心证据（骨架 §4 审稿应对第一行）。7 倍的区间不确定性意味着这句话可能是
全文第二硬的结论，也可能根本不该写。**一次配对计算就能定下来。**

同一次计算还顺带解决两件事：

1. **三个阳性检出的相关性**。它们共用 FedOSP-R 臂，骨架 §4.4 只能给出
   "corr 随 $s(\text{FedProx}-\text{FedAvg})$ 从 0.0070 到 0.0300 在 1.000 → 0.226 滑动"
   这样一个区间。拿到实测 $\sigma_d$ 之后，"算几次独立阳性"就从区间变成一个数。
2. **实测 ρ**（台账 §12.2 第 4 条）。骨架贡献 3 的四个 ρ（0.90/0.81/0.66/0.58）
   目前是由 $\sigma_d^2=2s_{\text{seed}}^2(1-\rho)$ **反解**的，依赖"两臂
   $s_{\text{seed}}\approx0.033$ 相等"这条近似。有了逐 seed 的两臂原始值就能直接实测，
   把贡献 3 从"四点观察 + 一个近似"升级为实测量。

**请一并报出每个 seed 的原始端点值（而不只是差值）**，否则上面第 2 条做不了。

⚠️ **不要为此改动任何已冻结的面板或预注册判据。** 这是对已有结果换配对方式，
不是新设计，也不改 Holm 族成员（族仍是 {FedProto, FedProx, MOON}，FedAvg 不在族内）。

## 2. ★ 三个次要端点的配对 CI，并且必须对称处理

**做什么。** 同样从已有的 50 个 run 的 `predictions.npz` 出发，逐 seed 算、按 seed 配对：

| 端点 | 现有（点估计） | 方向 |
|---|---|---|
| 等级 MAE | 0.4928 → 0.4623 | 有利 |
| ≥2 级误判率（T7 主指标） | 0.1393 → 0.1271 | 有利 |
| **referable 敏感性** | **0.7109 → 0.6947** | **不利** |

外加一组同样零成本、但信息量很大的量：**逐 seed 的误差跨度分布**
$P(|\hat y - y|{=}1)$ / $P({=}2)$ / $P({=}3)$ / $P({=}4)$ 四格。

### 2.1 为什么承重：它决定一个开放项是"假设"还是"发现"

完整分析见 [`分析_指标解离_2026-10-02.md`](分析_指标解离_2026-10-02.md)，这里给结论：

- **机制上可预期**：QWK 的权重 $(i-j)^2/16$ 让"远端换邻级"在 **4:1**（$d{=}2$）/
  **9:1**（$d{=}3$）的比价下划算；referable 阈值在 grade 1\|2 之间，而 Messidor-2
  阳性类的 **75.9%**（347/457）是 grade 2、离阈值只有一步。距离加权端点与阈值端点
  在阈值附近被**反向**优化。
- **但量级撑不起"发现"**：referable 子集 n = **457**，1.62 pp 只对应
  **约 7.4 例净翻转**，小于单臂二项抽样 SE（2.12 pp ≈ 9.7 例）。
  该下降在主端点上只值 **0.0020 QWK**（本比较 $\sigma_d$ 的 7%）。
- 所以骨架 §5.6 把它定为**假设 + 已指定的检验**，判定档位是**未证实**。
  **这一项就是那个检验。** 事先写下的预期是"CI 很可能跨零"
  （需要 $\sigma_d < 2.26$ pp 才判得动，而单臂抽样 SE 就已经 2.12 pp）——
  **两种结果都可写，所以不存在白做。**

四格误差跨度分布则直接判定另一件事：MAE 改善 0.0305 比"≥2 级误判换邻级"
能提供的上界 0.0122 大 **2.50 倍**，60% 的改善来自别处。
是"$P({=}2)$ 上升 + $P(\ge3)$ 下降"（尾部深处的收缩，不跨 referable 阈值），
还是"总误判率下降 1.83 pp"（就是更准了）？**四格一出来就知道，零成本。**

### 2.2 ⚠️ 对称处理要求（这一条优先于任何机制叙事）

**三个端点的证据强度完全相同：都是无区间的点估计。**
现在的叙述却把两个有利端点当成"改善了"、把不利端点当成"需要解释的异常"。
请二选一，**并对三个端点同时适用**：

| 方案 | 做法 |
|---|---|
| **A（推荐）** | 声明次要端点族 {MAE, ≥2 级误判率, referable 敏感性}，**族内 Holm 校正**，三者一起报 Δ / CI / $\sigma_d$ / 同向数 / $d_z$ |
| B | 三者**一律标注 exploratory**，不做任何显著性声称，只报点估计并显式写"无区间" |

**禁止**：对有利端点报"改善"、对不利端点报"落在噪声内"。反之亦然。
这条纪律与台账 §4.2（"阳性与零不得并列陈述为承担同等选择风险"）同源：
那一条管选择偏差的方向，这一条管**证据标准的对称**。
一篇以"噪声会计"为主张的论文，被抓到对自己有利和不利的端点用两把尺子，
是最致命的一种自相矛盾。

### 2.3 阈值指标的统计口径，三条

1. **用 McNemar 或配对比例区间，不要用非配对区间。** 两臂评的是同一批 457 个阳性例；
   非配对 SE（3.02 pp）把两臂共同的样本难易度方差算进误差，白白损失功效。
   **请直接报 McNemar 的 $b$ / $c$ 两个计数**——它们本身就是可审计量。
   参考（净差 7.4 例时）：$b+c$ 要 $\le 14.3$ 例才有 $p<0.05$，
   即两臂须在 **96.9%** 的阳性例上判断完全一致。
2. **seed 层与样本层分开报，不要混成一个数。** seed 层配对 t 量训练随机性，
   样本层 McNemar 量病人抽样。骨架 §4.6 已经区分这两项，这个端点照办。
3. **几百例上的比例必须并排写例数。** 建议一律写成 `0.6947（317.5/457）`。
   理由就是 §2.1 的演示：1.62 pp 像个效应，7.4 例像噪声，而它们是同一个数。

### 2.4 ★ 顺带请报一个量，它能化解台账 §13.9 第 3 条登记的冲突

**请对 FedOSP-R 逐 seed 报出 argmax 后的"预测为 referable 的总数"与特异度。**

台账 §13.9 第 3 条登记的冲突是：referable AUROC **+0.0090、10/10 seed 同向**（改善），
而敏感性**下降**。两者可以同时为真，而且能说清怎么同时为真：

| 量 | 读数 | 它量的是 |
|---|---|---|
| referable AUROC | +0.0090，10/10 同向 | **区分度**（无阈值） |
| referable 敏感性 | −0.0162（约 7.4 例） | **某一个工作点**上的召回 |
| 预测 referable 总数 | **请补** | **工作点移动了多少** |

台账 §6 已有一条同向线索：平均**软预测** referable 占比
FedAvg **26.46%** / FedOSP **23.76%** / 真实 26.20%，两臂差 **−2.70 pp**
（1744 张上约少判 47 张）。但它**不能直接用**——§6 测的是 **FedOSP**
（FSR 开启 + sqrt 聚合，而 sqrt 已被判有害），**不是 FedOSP-R**；
而且是软预测概率质量，不是 argmax 硬判读。所以需要 FedOSP-R 的 argmax 计数。

**为什么这一项便宜又关键**：如果预测阳性总数的降幅（约 47 张量级）确实大于
真阳性的降幅（约 7.4 例），那么**特异度在上升**——这是一次**工作点平移**，
不是区分度损失。那么整组数字用更少的假设就解释完了，
连 QWK 的权重结构都不需要动用。**这会把 §2.1 的解离假设进一步降权，是好事**：
论文少一个需要辩护的机制主张。

⚠️ 无论结论如何：**报工作点就必须同时报特异度 / 预测阳性数。**
只报敏感性下降而不报特异度，与 §2.2 禁止的不对称是同一个错误。

⚠️ **引用 457 之前请先核对分母。** 它来自仓库登记的等级分布
`EXPECTED_GRADE_DIST["messidor2"] = [1017, 270, 347, 75, 35]`、referable = grade ≥ 2、
分母取真阳性数。**若你们实际用的是别的分母（全体 1744、referable 取 ≥1、
或先做过阈值标定），上面所有例数失效**，请先告知口径。

## 3. ★ NPZ 顺序可恢复性：决定病人级 cluster bootstrap 能不能做

**问题。** 你们的 `predictions.npz` **没有保存 `image_id`**。标签向量与固定的 manifest
顺序一致，这说明顺序**很可能**没问题；但**仅凭 NPZ 本身无法排除同标签内部的重排**
——如果写出时发生过任何按标签分组、稳定排序或 shuffle，标签向量看起来完全正常，
而预测与病人的对应关系已经错位。这是典型的静默失败（台账 §11 记了 11 个同类）。

**建议的廉价核验（一次，单 seed）：**

```
在固定的 manifest 顺序上，对任意一个已完成的 seed 重跑一次推理，
把得到的预测向量与已存的 NPZ 逐元素比对。
```

**它能建立什么、不能建立什么——请按这个口径写，不要放宽：**

| 结论 | 能否建立 |
|---|---|
| 该 seed 的 NPZ 行序 = manifest 行序，因此可以**按行号**接上 `image_id` | ✅ **能**（逐元素相等是强证据） |
| 其余 49 个 run 也是同一顺序 | ⚠️ **只能在"写出代码路径对所有 run 相同"的前提下推广**。请同时确认写出 NPZ 的代码在这 50 个 run 之间**没有变过**（这正是第 4 项 git 提交要解决的问题——现在没有 commit hash 可查） |
| 预测本身正确 | ❌ **不能**。这只核对顺序，不核对模型 |
| 顺序错位时能定位错在哪 | ❌ **不能**。不相等只告出"不一致"，不给出置换。若不相等，正确的修复是**在写出端补 `image_id`**，不要去猜置换 |

**最彻底也最省事的做法**：直接在 NPZ 里加一个 `image_id` 数组，然后重跑那一个 seed。
一次性成本几乎相同，但从此不再需要任何推断。**强烈建议走这条。**

**为什么它承重。** 这是论文头号主张的直接延伸。

骨架 §4.6 的核心论断是：**seed 方差（SD = 0.033）大于测试集抽样方差
（病人级 cluster bootstrap 约 0.023）**，所以问题的性质是"重复不够"而不是"数据不够"。
但现在全文**每一个 CI 都是 seed 层配对 t**，它量的是**训练随机性**，
**不是病人抽样**。而 Messidor-2 是 1748 张 / 约 874 次检查，**约两张图一个病人**，
DR 又是双侧疾病——双眼高度相关，1744 张远不是 1744 个独立单位。

**一篇以噪声会计为卖点的论文，一定会被问"你们的区间把病人聚类算进去了吗"。**
现在的答案是"没有，而且暂时做不了"（台账 §10 已登记为 ❌ 待办，§12.2 记了它还需要
ADCIS 官方配对表）。顺序可恢复性是这条链上**我们自己能解决的那一环**；
配对表是对外依赖，但顺序不是。参考量级：眼间 ICC 取 0.3/0.5/0.7 时设计效应
1.30/1.50/1.70，457 个阳性例的有效 n 掉到 352/305/269，**样本层区间要宽 14%–30%**。

## 4. 把 50 run 的证据链提交进 git：当前最大的项目风险

**做什么。** 把 `bn/feed-quality-training/user/gushiyu/projects/flosp/` 下的产物提交，
至少包括：

- `audits/final/FINAL_EVIDENCE_REPORT_CN.md`（入口）
- `audits/final/paired_core_methods_seed3_12.json`（统一审计）
- `tables/final/Table3_paired_qwk.md`、`tables/final/Table4_resources.md`（+ 其余 2 主表 3 附表）
- `figures/main/Figure3_qwk_forest.pdf`、`figures/main/Figure5_mde_detection_boundary.pdf`（+ 其余主图附图）
- `scripts/build_paper_evidence.py`（一键复现）
- 旧配对审计脚本里 "n=3" 硬编码警告的修复

**为什么它是头号风险，而不只是"该做的事"。**

这不是一句泛泛的"记得备份"。它与一条**已经存在的**局限叠加：

> **每个 run 的 `result.json` 里不记录 git / worktree hash。**

也就是说，这 50 个 run 的**溯源本来就弱于理想状态**：拿到一个数字，没法确定它是哪一版
代码产出的。台账 §11 的 15 个缺陷里有一条正是"同一个量在仓库里同时存在两个值
（表写 61、脚本打印 59）而无任何提示"——**没有 commit hash，这类分叉无法被发现，
只能被撞上。**

现在再叠加"整条链不在版本控制里"，两个弱点相乘：

| 单独存在时 | 叠加之后 |
|---|---|
| 没有 hash，但文件在 git 里 → 还能用提交时间与 diff 反推 | **两者都没有 → 完全无法重建"这张表是哪一版代码出的"** |
| 文件不在 git，但 run 里有 hash → 还能定位代码版本 | 同上 |

而这 50 个 run 是论文 4 张主表、5 张主图、全部 CI 的**唯一数据源**。
兄弟项目有过现成教训：同名 run 散落在多个目录、同一格数值不同，
最后只能靠人工定一个"规范副本优先级表"来消歧，而文档里明写
**用全部副本会静默改变 seed 数与均值**。那是在有文件的情况下；
我们现在连文件都还没纳管。

**具体建议**（按性价比）：

1. **先提交，再优化。** 立刻把现有产物提交，不要等目录结构想好。
2. **在 `result.json` 里补 git hash**（`git rev-parse HEAD` + `git status --porcelain`
   是否为空）。这对未来所有 run 都生效，成本是几行代码。
3. **为这 50 个 run 补一条"已知局限"记录**：它们产出时 hash 未记录，
   因此溯源依赖提交历史而非 run 自身。**如实写进论文的 reproducibility 一节**——
   骨架 §6.1 的主张正是"15 个已修缺陷中 11 个是静默失败"，
   在这里对自己诚实比把它藏起来更有说服力。

## 5. 确认 Brier 的类别数 K（前一份交接的 §8.1，仍未回收）

**数值口径已核定为 $[0,2]$**（台账 §12.3，决定性判据是分布无关上界：
校准的 5 类模型必有 $\mathrm{Brier}_{[0,2]}\le0.8$，而 0.507 读成 $[0,1]$ 需要
$\mathbb{E}\lVert p\rVert^2=-0.014<0$，不可能）。

**但 K 从未被核对。** 若你们是在 **referable 二分类**上算 Brier，
均匀预测的参照点变成 **0.5 / 0.25**（而不是 5 类的 0.8 / 0.4），
**上面整条推理全部不适用**，台账 §12.3 的三条判据一条都不能用。

> **请求**：在报告里显式写出 K。
> **最可靠的检出办法**：拿同一份 `predictions.npz` 用双方实现各算一遍，
> 比值恰为 **2.000** 就是数值口径不一致，**1.000** 则一致；
> 若两边类别数不同，差异不会是整洁的 2 倍，而是量级跳变。
> 没有 npz 时看区间：5 类问题上 0.45–0.65 只能是 $[0,2]$，0.22–0.33 只能是 $[0,1]$。

**为什么还要再提一次。** Brier 是骨架 §3.4 的四个辅端点之一，
而 §5.5 的排除性证据（oracle 先验重加权使 Brier 0.507 → 0.604）是全文
"失真在条件概率结构而非边际先验"这个机制结论的**唯一支撑**。
K 不对，这段推理就不成立；而它不报错、不告警。

## 8. 明确不做的事

### 8.1 ❌ 不再跑任何"救方法"的实验

**证据链已经闭合，这一条没有例外。** FedOSP-R 相对 FedProto 是 **+0.00045**，
95% CI **[−0.0101, +0.0110]**，$\sigma_d=0.0147$ 是全面板最紧的一格——
**这是精确零，不是功效不足**。四个组件逐个、2×2 交互项（J = −0.0160，方向相反）、
相对同族基线的增量，全部已证伪。

具体不要做的：

- ❌ 不换 MOON / FedProx 超参，不为把 MOON 推过 R1 而加 seed。
  **看到 R3 之后再决定样本量，就是按结果选择样本量**，会毁掉预注册的全部价值。
- ❌ 不做基于少量 seed 的参数扫描。在 $\sigma_d\approx0.02$–$0.03$ 上
  （n=10 的 MDE ≈ $\sigma_d$），这是**按噪声选择**，正是本文在批评的做法。
- ❌ 不改动已冻结的面板与预注册判据（含 R1–R4、Holm 族、方差分解的 60%/30% 阈值、
  $\delta_{eq}$）。哪怕只是"补一个 `--eval-external-every`"也不行。
- ❌ 不事后把 FedALA 升到 A 层 / n=10。
- ❌ 不把 MOON 的 R3 写成"支持 H1"或"倾向支持 H2"。

### 8.2 ✅ 以下四项**正确地**留在范围之外，请保持

| 项 | 为什么跳过是对的 |
|---|---|
| **LOCO**（leave-one-center-out） | 成本高，且不改变创新裁决——裁决已由 vs FedProto 的精确零闭合 |
| **第二个外部测试集** | 同上；且新数据集会引入新的协议偏移（台账 §3 已有一次：RETFound 的 IDRiD 0.822 实为跨数据集评估），净增可信度不明 |
| **t-SNE / UMAP** | **你们给的理由是对的，请原样保留**：层、seed、投影参数都是**事后选择**，会增加分析自由度。在一篇主张"文献在噪声底线以下报结论"的论文里，加一张参数可调的定性图是自相矛盾。本项目在"可调阈值的启发式"上栽过三次（README 的自动平台检测三版，每版偏差都朝同一方向），这条教训同源 |
| **模块搜索 / 架构搜索** | 搜索空间越大、$\alpha$ 花得越多；在 $\sigma_d\approx0.027$ 上搜索等于拟合 seed 噪声 |

**一句话**：本清单里没有一项需要新的 GPU 机时去争取一个更好的结论；
前三项只是把**已有的结论配上它们本该有的误差棒**。
